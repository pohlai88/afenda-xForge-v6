# Configure Shadcn Studio Pro as the frontend UI authority

We are standardizing this repository on **Shadcn Studio Pro + shadcn/ui** for frontend implementation.

Do **not** redesign, restructure, migrate, or refactor the application yet.

Your first task is only to configure, validate, and document the Shadcn Studio development environment safely.

## 1. Inspect the repository first

Before changing anything, inspect:

* package manager
* monorepo/workspace structure
* frontend application location
* existing `components.json`
* existing `CLAUDE.md`
* existing `.claude/`
* existing `.env*`
* `.gitignore`
* Tailwind configuration
* current shadcn/ui setup
* current component directory and aliases
* existing Shadcn Studio Admin Template implementation

Do not assume paths.

Do not initialize a second shadcn project if one already exists.

Do not overwrite existing configuration blindly.

---

## 2. Preserve the existing frontend architecture

The current **Shadcn Studio Admin Template is our frontend foundation**.

Do not introduce:

* a new design-system abstraction layer
* ADL
* wrapper primitives such as `AfendaButton`, `AfendaCard`, etc.
* another theme architecture
* another component library
* competing primitive APIs
* arbitrary Tailwind styling conventions

We will extend Shadcn Studio through composition rather than rebuilding its primitives.

---

## 3. Configure Shadcn Studio Pro CLI registries

Use the current **shadcn CLI v4** approach.

Merge the Shadcn Studio registries into the existing `components.json` without destroying existing configuration.

Required registries:

* `@shadcn-studio`
* `@ss-components`
* `@ss-blocks`
* `@ss-pages`
* `@ss-themes`

Premium registries must use environment-variable authentication.

Expected credential variables:

```env
EMAIL=
LICENSE_KEY=
```

Do NOT ask me to paste secrets into source files.

Do NOT print secret values.

Do NOT commit credentials.

Ensure the appropriate local environment file is ignored by Git.

If the variables are absent, prepare the configuration with placeholders and clearly tell me what I need to populate locally.

---

## 4. Configure Shadcn Studio MCP for Claude Code

Check whether `shadcn-studio-mcp` is already configured.

If it is already installed, validate it instead of creating a duplicate configuration.

If it is missing, configure it according to the current official Shadcn Studio Claude Code instructions.

The official pattern is:

```bash
claude mcp add --transport stdio shadcn-studio-mcp --scope user -- npx -y shadcn-studio-mcp API_KEY=YOUR_API_KEY EMAIL=YOUR_EMAIL
```

Credentials must come from the user's Shadcn Studio Pro/MCP account configuration.

Never hard-code credentials into repository files.

Never commit them.

---

## 5. Install the Claude Shadcn Studio commands

Ensure the repository contains:

```text
.claude/commands/
├── cui.md
├── iui.md
├── rui.md
└── ftc.md
```

These should invoke the corresponding Shadcn Studio MCP instruction tools:

* `/cui` — create/customize using Studio blocks
* `/iui` — inspire/generate using Pro Studio resources
* `/rui` — refine an existing implementation
* `/ftc` — Figma-to-code workflow when Figma MCP is available

Use the current official Shadcn Studio command definitions.

Do not replace unrelated existing Claude commands.

---

## 6. Preserve and augment CLAUDE.md

Shadcn Studio provides an official AI instruction file.

Do **not** execute an overwrite such as:

```bash
curl -o CLAUDE.md ...
```

if this repository already has a `CLAUDE.md`.

Instead:

1. retrieve the current Shadcn Studio instructions to a temporary file;
2. compare them with our existing `CLAUDE.md`;
3. merge only the relevant Shadcn Studio rules;
4. preserve all existing repository-specific architecture instructions.

Add the following project rule:

## Shadcn Studio frontend authority

For frontend work, use this selection hierarchy:

```text
Existing implementation
        ↓
Shadcn Studio Template
        ↓
Shadcn Studio Page
        ↓
Shadcn Studio Block
        ↓
Shadcn Studio Component
        ↓
shadcn/ui primitive
        ↓
custom composition
```

Before creating custom UI, search Shadcn Studio first.

Do not manually recreate something that already exists in the Studio registry.

Prefer composition over abstraction.

Prefer existing component variants over one-off styling.

Use semantic theme tokens rather than arbitrary colors.

Preserve the visual language of the existing Shadcn Studio Admin Template.
