
# 8. Shadcn Studio implementation policy

Afenda uses the existing Shadcn Studio / Base UI design system.

Selection order:

```text
1. existing project pattern
2. existing shared Afenda primitive
3. Shadcn Studio template pattern
4. Shadcn Studio block
5. Shadcn Studio component
6. existing Base UI primitive
7. custom composition only when justified
```

Do not introduce a parallel primitive system.

Do not introduce Radix into a Base UI application unless the repository already authorizes it.

Do not create wrapper components merely to rename existing primitives.

Do not blindly install a Shadcn Studio block without inspecting dependencies and primitive compatibility.
